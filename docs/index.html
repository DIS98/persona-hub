01 / 软件介绍

这是什么

先把边界说清楚，再谈功能。

人格中枢处理的是「把一份人格提示词写进多个 AI 客户端」这件小事里最容易出问题的三处：写之前有没有原文、写之后有没有校验、不想要了能不能完整撤回。

它只走客户端公开的扩展点与普通文本文件——人格文件、托管提示词目录、记忆层、自定义指令——不改宿主程序文件、不注入进程、不依赖网络完成任务。同类工具常只记路径不存内容，这里改成写前快照、内容寻址备份、写后逐字节回读。

编辑、差异预演、注入、检测、还原集中在同一界面；所有写操作走一个「全或无」事务，任何一步回读不一致就用刚拍的快照整笔回滚。

写前快照逐字节还原差异预演幂等与共存注入检测生效自检
02 / 功能

能做什么

每一条都对应仓库里真实存在的代码路径。

01 / FEATURE

写前快照

提交第一步拍现状快照，记录原文件是否存在、大小、权限与原文；原本不存在的文件还原时删除，而不是留一个空壳。

02 / FEATURE

逐字节还原

快照按 SHA-256 回读比对；停用第三方注入时用二进制存档，避免换行符被文本模式改写。

03 / FEATURE

差异预演

提交前生成 unified diff 与增删行数、字节数统计，预览阶段不写任何文件。

04 / FEATURE

幂等与共存

带 id 的区块就地替换，重复注入不叠加；多个默认并存于同一文件，显式选「替换」才只留一份，冲突时给出告警。

05 / FEATURE

注入检测

本工具区块、第三方特征签名、结构异常三类扫描并按人格归组；认不出的注入明确标为「未知」，不猜测。

06 / FEATURE

生效自检

从会话记录读回这一轮真正被读取的内容，给出生效 / 沿用 / 过期 / 部分 / 缺失 / 未注入的判定。

07 / FEATURE

读取窗口预算

按目标声明的读取上限计算剩余额度，注入位置超窗或挤掉使用者自己的规则时给出分级告警。

08 / FEATURE

模板体系

frontmatter + 正文、继承链、变量渲染、导入任意 Markdown、内置五套模板，界面可一键插入六节骨架。

09 / FEATURE

自定义目标

侧栏手填名称与路径，与自动检测并列显示；移除只删配置，不动已写入的文件。

10 / FEATURE

本地优先

断网满功能、纯标准库 Python 可审计、零设备标识采集、不上传任何内容。

03 / 快速开始

四步跑起来

只想用，就走前三步；想改，再看第四步。

1

选一种运行方式

推荐直接下载桌面安装包；也可以下载单文件可执行程序，或用 Python 源码运行。

Releases → desktop-0.3.17 → persona-desktop-0.3.17-62f3ca05-setup.exe
Releases → core-1.14.14    → persona-hub-1.14.14-50af66ab.zip
2

启动

桌面安装包走向导式安装，不需要管理员权限，卸载时保留数据。源码运行只需 Python 3.10+，无第三方依赖。

python hub.py                # 默认图形界面
python hub.py --no-gui       # 只起本地服务
python hub.py --port 8900    # 指定起始端口（默认 8799）
3

完成第一次注入

在「人格与注入」页选中一个人格 → 右侧抽屉编辑 → 填变量 → 点「预览差异」确认 → 选「并存」或「替换」→ 写入。

① 侧栏选人格
② 悬停铅笔 / 「改这个人格」打开抽屉
③ 预览差异（只读，不写文件）
④ 写入方式与变量确认后提交
⑤ 在「注入管理」页看检测结果
4

写出自己的人格模板

模板是带 frontmatter 的 Markdown，支持 extends 继承与 {{变量}} 占位；界面「插入骨架」可一键生成六节结构。

---
name: 我的助手
extends: base-direct
tags: [general]
---

【身份】
{{角色描述}}

【完成判据】
…
04 / 使用方法

日常怎么用

操作路径、配置项与已知边界。

三个页签

  • 人格与注入：侧栏选人格、抽屉编辑、变量填写、差异预演、写入方式、Ctrl+S 保存。
  • 注入管理：目标客户端与自定义目标、生效自检、格式遵从、记忆层、宿主模板插槽、重新扫描、开关与批量移除。
  • 备份与还原：快照列表、还原到此、清理旧快照、操作日志。

人格模板写法

  • 文件放在 personas/ 下，以 --- 开头的 frontmatter + 正文；字段含 id、name（必填）、desc、extends、tags、version、author、size_limit。
  • extends 支持链式继承，父正文在前、子正文在后；循环继承会被拒绝。
  • {{变量}} 由界面变量栏填写，未填值会被单独报出，不会静默变成空串。
  • 六节骨架：身份 / 完成判据 / 方法与硬约束 / 输出规格 / 不做的事 / 不确定时。

停用、移除与还原

  • 本工具注入停用后只留一行说明，正文不写进文件；再次启用时 id 不变。
  • 第三方注入停用后整块移入存档，原位留标记，可再启用；移除按字符偏移精确切除。
  • 删除人格前会先拍一份快照；任何一次写入都能从备份页回到写入前的状态。

升级与生效

  • 顶栏升级入口：检查 → 下载 → 校验 → 暂存 → 下次启动应用；桌面与内核使用两份独立清单。
  • 升级包只接受 HTTPS，下载后校验 SHA-256 与体积上限，解压时拦截路径穿越，应用时跳过数据目录。
  • 改动身份类文件后，需要完全退出宿主客户端（含托盘）再打开才会生效。

关键设计决策

快照先于写入提交的第一步是拍摄现状快照，顺序不可颠倒；否则回滚没有依据。
全或无事务逐文件原子写完成后统一回读，任一不一致就用刚拍的快照把已写的全部还原；写操作加进程内锁，防并发覆盖。
只走官方扩展点不修改宿主程序文件与依赖包，不注入进程，把宿主升级带来的冲突面降到最小。
判定靠证据目标是否可用看目标文件或标志物是否存在，不靠父目录猜测；注入状态靠完整区块标记解析，不靠子串包含。
正文防伪造写入前把正文里伪造的区块标记替换为全角字符，防止内容伪装成控制结构。
前后端分离桌面外壳不放后端源码副本，通过本机 HTTP API 与页面心跳通信；界面样式只在本窗口内注入。
协议层收敛仅允许回环 Host、限定请求体大小与内容类型，补充 nosniff 与同源读取策略。

常见问题

会修改宿主程序文件吗？

不会。只写客户端公开的扩展点与普通文本文件，不改二进制、不注入进程。

断网能用吗？

能。核心功能不依赖网络；只有主动检查更新时才会发起请求。

支持哪些客户端？

内置常见文本型通道的适配器，并允许在侧栏自定义目标；适配器注册表可扩展。

写入失败会留下半截内容吗？

不会。任一文件回读不一致，整笔事务会用快照还原到写入前。
